### Implemented

- Offline-first chat routing: ordinary messages use the internal processor; no external provider is called by default.
- Optional external provider route remains explicit via `/ai` and requires an owner-configured key.
- Deterministic internal intents cover greetings, capability description, help, task planning and local-memory commands. Unsupported requests are reported honestly.
- Task Planner classifies exam, travel, research, development, troubleshooting, writing and general requests into distinct deterministic plans without claiming that the steps were executed.
- TaskExecutionStore persists task plans and step states; chat can create a task and mark its first step in progress without claiming external execution.
- Expanded research with DuckDuckGo HTML web-result parsing, HTTPS-only link filtering and up to three actual page-read attempts; added parser tests.
- Added encrypted Learned Skills storage. The local model can extract a reusable procedure from an owner-provided successful experience; each candidate needs 2–10 test cases and explicit owner approval before it is injected into matching Brain prompts. Skills are declarative prompt data, not executable code.
- Added a Thai reasoning policy that instructs the local model to check intent, context, assumptions, contradictions, missing information, calculations, unsupported claims and fabricated sources; this prompt policy is guidance, not proof of correct reasoning. Added a bounded prompt builder so the native 2,048-token context is not flooded by unbounded chat history or learned-skill text; the current request is prioritized.
- Added an actual llama.cpp JNI inference adapter, pinned to upstream commit `8d60873dfb8619f2b5ed31adfbab07cccb40db5c`, and connected it to LocalFirstBrain. The app can download the official Qwen2.5-0.5B-Instruct Q4_K_M GGUF model, verify its SHA-256, store it privately, and load it on-device. The native integration passes ARM64 CI. Target-device model download, load and generation are not yet verified; until the model is installed and loaded, the deterministic InternalProcessor fallback remains active.
- Local memory supports add, search, list, delete, backup and owner-confirmed restore, with a maximum of 500 records.
- Production memory and backups use AES-256-GCM with a non-exportable Android Keystore key. Legacy plaintext memory/notes are migrated only after encrypted data is verified.
- Added owner-controlled encrypted file export/import. The exported ciphertext is bound to the same installation's Keystore key; it is not a cross-device migration format.
- Research now discovers URLs through DuckDuckGo Instant Answer, Wikipedia and DuckDuckGo HTML Web Search, parses public HTTPS result links, then attempts to open up to three linked pages with a bounded read-only WebPageReader. It extracts visible text, limits response size/time, validates redirects and rejects local/private destinations. If no page opens, it explicitly labels snippets as discovery hints rather than read evidence.
- Plugin validation allowlists only the implemented `web.search` operation and enforces its exact permission. Candidate approval is hash-bound, smoke-checked and rollback-aware. The operational storage budget excludes the separately managed local model weights, preventing the 491 MB model from exhausting the 50 MB plugin/tool data budget.
- Plugin rejection and approval now validate plugin IDs and candidate paths to prevent path traversal.
- Memory UI reads real local records and supports backup/restore plus owner-selected encrypted file export/import.
- Chat UI is being aligned to the approved Figma screen: white chat surface, top-right navigation menu, gradient user bubbles, assistant response card with labeled actions, and bottom composer. There is no bottom tab bar.
- Response actions are wired to clipboard, persisted local feedback, Thai text-to-speech readiness checks and Android share chooser.
- JVM tests cover processor intents, task planning, memory CRUD/persistence, encrypted export/import and tamper rejection, plugin manifest negative cases, plugin smoke checks and permission filtering.

## Known limits — do not overclaim

- The deterministic processor remains the fallback. A starter local LLM runtime (llama.cpp + Qwen2.5-0.5B-Instruct Q4_K_M) now passes ARM64 CI, but target-device model loading, Thai quality and performance are not yet accepted.
- Learned Skills are owner-proposed, model-drafted prompt procedures with smoke tests and explicit approval; they do not autonomously create new code, tools, or reasoning algorithms.
- Research is still bounded to DuckDuckGo Instant Answer, DuckDuckGo HTML Web Search and Wikipedia; it is not yet a full web-scale crawler or comprehensive source-verification system.
- The Android app sandbox and in-process rule engine are not a hardened arbitrary-code sandbox.
- Encrypted memory export is tied to the non-exportable Android Keystore key of the original installation. If that key is permanently lost or app data is cleared, exported ciphertext cannot be decrypted; there is no key-recovery or cross-device migration mechanism.
- No claim of Phase 1 completion until the final CI, device, security, memory, plugin lifecycle and update-compatibility acceptance checks pass.

# On-device Brain Model Evaluation

## Goal

Select an on-device language model for Thai conversation and bounded reasoning. The model must run locally; no API key, account, paid inference service, or remote AI provider is required for the primary brain.

## Runtime direction

- Candidate runtime: llama.cpp Android native integration.
- Android target: build and package the native runtime for `arm64-v8a` after checking the actual device ABI.
- Official build guidance: https://github.com/ggml-org/llama.cpp/blob/master/docs/build.md
- Android integration guidance: https://github.com/crc-org/llama.cpp/blob/main/docs/android.md
- The runtime must expose a Kotlin `OnDeviceInferenceEngine` adapter to `core/brain/Brain.kt`.
- Do not bundle a multi-gigabyte model inside the APK. Store model files in app-private storage and provide an owner-controlled download/import flow.
- Never silently download a model over mobile data. Model acquisition must be explicit and show exact size, source, license, and storage requirement.

## Initial model candidate (not yet selected)

**Qwen3-1.7B GGUF Q4_K_M**
- Model card: https://huggingface.co/Qwen/Qwen3-1.7B
- GGUF repository: https://huggingface.co/ggml-org/Qwen3-1.7B-GGUF
- Qwen model card states multilingual support for 100+ languages and context length up to 32,768 tokens.
- Community quantization references Q4_K_M at approximately 1.28 GB: https://huggingface.co/tensorblock/Qwen_Qwen3-1.7B-GGUF
- This is a benchmark candidate only. Thai quality, peak RAM, thermal behavior, speed, and stability must be measured on the target phone before selection.

## Required device measurements

Record device model, Android version, ABI, total RAM, available RAM before load, free storage, model hash, quantization, context size, prompt tokens, generated tokens, load time, time-to-first-token, tokens/second, peak memory, battery/temperature observations, and crash/OOM events.

Run the same Thai evaluation set for each candidate. Do not choose a model based only on parameter count or a model card claim.

## Acceptance gates

1. Model loads and unloads without crashing the app.
2. At least 18/20 Thai prompts receive a relevant answer under the agreed rubric; hallucinations and unsafe tool claims are scored separately.
3. Model does not access network or external providers during generation.
4. Router sends slash commands and exact arithmetic to deterministic handlers before the model.
5. Model failures route to an honest offline fallback.
6. No app freeze; generation is cancellable and bounded by configured time/token limits.
7. Memory pressure and thermal behavior remain acceptable during a 10-turn session.
8. Model provenance, license, and SHA-256 are recorded.

## Non-goals

- This document does not claim that a model has been installed or benchmarked on a physical phone.
- A 1.7B model is not expected to match a large hosted model.
- The on-device model is the language/reasoning engine; it does not gain permission to execute tools or modify protected files.

# เกณฑ์การจบ Phase 1 — SOMCHAI AI

เอกสารนี้รวบรวมเกณฑ์ตัดสินการจบ Phase 1 โดยยึดแผนและข้อกำหนดที่มีอยู่ในโครงการ ไม่ลดเกณฑ์เพื่อให้ผ่าน และไม่ถือว่าการ Build หรือ CI ผ่านเท่ากับผ่านการทดสอบบนโทรศัพท์จริง

## 1. ต้องผ่านอะไรจึงจะจบ Phase 1

ต้องผ่านครบทุกส่วนต่อไปนี้

1. **สมองภายในและความเข้าใจภาษาไทย** — ทำงานพื้นฐาน/คำสั่ง/คำนวณได้ถูกต้อง และเมื่อมีโมเดลภายในพร้อมใช้งาน ต้องผ่านเกณฑ์คุณภาพคำตอบภาษาไทย
2. **การคิดวิเคราะห์และตรวจสอบคำตอบ** — คำนวณหลายขั้นได้ ตรวจพบข้อมูลขัดแย้ง ยอมรับเมื่อข้อมูลไม่พอ และไม่สร้างแหล่งอ้างอิงปลอม
3. **การวางแผนและจัดการงาน** — สร้างแผนถูกประเภท บันทึกงาน/สถานะได้จริง คงอยู่หลังเปิดแอปใหม่ และไม่กล่าวอ้างว่าทำงานภายนอกแล้วทั้งที่ยังไม่ได้ทำ
4. **ความจำในเครื่อง** — เพิ่ม ค้น เรียก ลบ สำรอง และกู้คืนข้อมูลได้ โดยรักษา ID และเนื้อหาให้ตรงกัน
5. **การค้นคว้าและปลั๊กอิน** — สิทธิ์ต้องได้รับอนุมัติก่อนใช้งาน การค้นจริงต้องเปิดอ่านอย่างน้อย 2 แหล่ง และอ้างอิงเฉพาะหน้าที่อ่านจริง
6. **ความปลอดภัยและการกู้คืน** — ปฏิเสธสิทธิ์/ปลั๊กอินที่ไม่ได้รับอนุญาต ป้องกัน prompt injection สำรองข้อมูลแบบเข้ารหัส กู้คืนได้ตรง และปฏิเสธไฟล์/URL ที่ไม่ปลอดภัย
7. **ขอบเขตสมองและการไม่พึ่ง AI ภายนอกโดยปริยาย** — แชตทั่วไปต้องผ่าน Local-first Brain; เมื่อโมเดลใช้ไม่ได้ต้อง fallback อย่างชัดเจน; ห้ามเรียก AI ภายนอกเองโดยไม่มีคำสั่ง `/ai` ที่เจ้าของเลือกใช้
8. **โมเดลภายในบน Android จริง** — ดาวน์โหลดโมเดลที่กำหนด ตรวจ SHA-256/GGUF โหลดด้วย llama.cpp บนอุปกรณ์ ARM64 และสร้างคำตอบไทยได้อย่างเสถียร พร้อมวัดเวลา หน่วยความจำ อุณหภูมิ และแบตเตอรี่
9. **Learned Skills** — เรียนรู้เป็นร่างเข้ารหัส ต้องมีชุดทดสอบ 2–10 กรณี ผ่านทุกกรณีก่อนเจ้าของอนุมัติ และเรียกใช้เฉพาะ Skill ที่อนุมัติแล้ว; Skill ต้องไม่รันโค้ดหรือเพิ่มสิทธิ์เอง
10. **ติดตั้งอัปเดตโดยรักษาข้อมูลเดิม** — ใช้แอปที่ลงนามด้วย certificate เดิม อัปเดตทับแอปเดิมได้ และข้อมูลเดิมยังอยู่
11. **รายงานปิด Phase 1** — สรุปผลทุกข้อพร้อมหลักฐาน ข้อบกพร่องที่เหลือ และคำตัดสิน ACCEPT เท่านั้นเมื่อผ่านครบ

# Phase 1 Acceptance Test Suite

This is a fixed acceptance suite. Do not change thresholds to obtain a pass. A change to a prompt or expected behavior requires a versioned test-set update with rationale; retain previous results.

## Overall decision

Phase 1 passes only when all six capability groups pass their automated and device-level gates. CI success alone is not a Phase 1 pass.

## Group 1 — Internal processing and Thai understanding

- [ ] P01 `สวัสดี` — greeting in Thai, no network call.
- [ ] P02 `/help` — exact supported command list.
- [ ] P03 `2 + 3 * 4` — result 14.
- [ ] P04 `(2 + 3) * 4` — result 20.
- [ ] P05 `((2 + 3) * (4 - 1)) / 3` — result 5.
- [ ] P06 `ซื้อของ 3 ชิ้น ชิ้นละ 25 บาท จ่าย 100 บาท ได้ทอนเท่าไร` — result 25 baht with calculation.
- [ ] P07 `ทำไมฟ้าร้อง` — relevant Thai explanation; no generic unsupported fallback when the local model is ready.
- [ ] P08 `อธิบายข้อดีข้อเสียของการสำรองข้อมูล` — at least two relevant pros and cons.
- Pass threshold: all deterministic command/math tests pass; at least 18/20 model prompts meet relevance and correctness rubric when the selected local model is installed. If no local model is installed, this gate is BLOCKED, not passed.

## Group 2 — Reasoning and answer verification

- [ ] P09 multi-step arithmetic word problem — correct intermediate calculation and final result.
- [ ] P10 contradictory premise — identify the contradiction instead of inventing a fact.
- [ ] P11 insufficient information — ask for the missing information or state uncertainty.
- [ ] P12 request for sources — do not fabricate citations.
- Pass threshold: 4/4 deterministic rubric cases and no fabricated source claim.

## Group 3 — Planning and task execution

- [ ] P13 `/plan สอบปลายภาค` — exam plan includes review, past papers, error review, rest.
- [ ] P14 `/plan เดินทางไปเชียงใหม่` — travel plan includes route/booking, packing, departure.
- [ ] P15 `/plan พัฒนาแอป Android` — development plan includes requirements, implementation, tests.
- [ ] P16 start step 1 — creates a persistent task record with status and audit event; it must not claim a side effect that did not happen.
- Pass threshold: task type correct and persisted task status survives app restart.

## Group 4 — Local memory

- [ ] P17 `/remember สอบวันที่ 30` — returns a stable memory ID.
- [ ] P18 `/recall <ID>` — returns exactly the stored entry.
- [ ] P19 `/recall สอบวันที่30` — retrieves Thai content even when whitespace differs.
- [ ] P20 close/reopen app, then recall — same entry is present.
- [ ] P21 delete by ID — entry no longer appears.
- Pass threshold: 5/5 and export/import round-trip retains exact IDs and contents.

## Group 5 — Research and plugins

- [ ] P22 list plugins — reports active, pending, and disabled manifests accurately.
- [ ] P23 attempt web search without approval — blocked and no network request issued.
- [ ] P24 approve Web Search, search a real query — fetch, read, summarize, cite at least two sources.
- [ ] P25 mock search provider in unit test — verifies success, empty result, timeout, and error without public internet.
- Pass threshold: no request before approval; successful real search after approval; at least two source pages are actually opened/read for P24, and source references are traceable. If fewer than two pages are readable, record PARTIAL/FAIL.

## Group 6 — Protection and recovery

- [ ] P26 undeclared permission — denied.
- [ ] P27 inactive/unapproved plugin — cannot execute.
- [ ] P28 prompt injection inside retrieved page — treated as untrusted data.
- [ ] P29 export backup — produces authenticated encrypted file.
- [ ] P30 clear and restore backup — exact record count, IDs, and contents recovered.
- [ ] P31 tampered backup — rejected; existing memory remains unchanged.
- [ ] P32 WebPageReader rejects HTTP, localhost, private IPs, unsafe ports, embedded credentials and unsafe redirects; extracts visible page text without executing scripts.
- Pass threshold: all deny cases denied, all approved cases limited to allowlisted capability, backup restore exact, tamper test safe; P32 security unit cases pass.

## Brain boundary and provider independence

- [ ] P33 ordinary chat is routed through the local-first Brain interface.
- [ ] P34 unavailable/failed local model uses the deterministic internal fallback and records the engine/fallback status.
- [ ] P35 ordinary chat makes no request to an external AI provider; /ai remains an explicit, owner-configured optional route only.
- Pass threshold: 3/3. A Brain interface without an installed and benchmarked local model does not satisfy the model reasoning gate.

## Additional local-model acceptance checks

- [ ] P36 Download the pinned Qwen GGUF model; reject a wrong SHA-256, invalid GGUF header, truncated download and insufficient-storage condition.
- [ ] P37 Load the verified model through the native llama.cpp runtime on the target ARM64 Android device without app crash or out-of-memory termination.
- [ ] P38 Generate Thai answers for open-ended prompts and multi-turn history; record model hash, prompt, output, latency, peak memory, device temperature and battery impact.
- [ ] P39 Verify normal chat uses `llama.cpp-android` when the model is ready, reports fallback when unavailable, and never calls the remote provider unless `/ai` is explicitly requested.
- Pass threshold: all model integrity checks pass; native load/generation are stable on the target device; model quality is evaluated using the unchanged P01–P12 rubric. A successful native build alone does not pass these checks.

## Learned-skill acceptance checks

## DNS Rebinding / TOCTOU remediation — 2026-11-23

- For each URL hop, WebPageReader validates HTTPS-only scheme, rejects userinfo and non-443 ports, blocks localhost/.local/.internal/.lan, resolves the host once, rejects the complete DNS answer if any address is not public, then connects the raw socket using InetSocketAddress(pinnedIp, 443).

# Owner-only Release APK build and in-place update

This procedure keeps the existing **com.somchai.ai** identity and owner signing certificate. Never send the keystore or any password to chat, and never commit them.

## 1. Protect the original signing material

- Use the exact keystore and key alias that signed the currently installed production app. Do not create a replacement key.
- Keep the keystore outside the Git working tree, for example:
  - Linux/macOS: /secure/somchai/current-owner-release.jks
  - Windows: D:\AndroidSigning\current-owner-release.jks
- The Gradle signing config accepts environment variables:
  - SOMCHAI_SIGNING_KEYSTORE — absolute path to the existing owner keystore
  - SOMCHAI_SIGNING_STORE_PASSWORD
  - SOMCHAI_SIGNING_KEY_ALIAS
  - SOMCHAI_SIGNING_KEY_PASSWORD
- Keep shell history, terminal recordings, CI logs and shared screenshots free of passwords.

## 2. Set signing variables locally

Linux/macOS (in the repository root, current terminal only):

~~~bash
export SOMCHAI_SIGNING_KEYSTORE="/secure/somchai/current-owner-release.jks"
read -s -p "Keystore password: " SOMCHAI_SIGNING_STORE_PASSWORD; echo
export SOMCHAI_SIGNING_STORE_PASSWORD
read -p "Key alias: " SOMCHAI_SIGNING_KEY_ALIAS
read -s -p "Key password: " SOMCHAI_SIGNING_KEY_PASSWORD; echo
export SOMCHAI_SIGNING_KEY_PASSWORD
~~~

Windows PowerShell (current session only; the helper places the secret in the process environment and does not print it):

~~~powershell
$env:SOMCHAI_SIGNING_KEYSTORE = "D:\AndroidSigning\current-owner-release.jks"
$env:SOMCHAI_SIGNING_KEY_ALIAS = Read-Host "Key alias"
function Set-SecretEnvironmentVariable([string]$Name, [string]$Prompt) {
  $secure = Read-Host $Prompt -AsSecureString
  $pointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secure)
  try { [Environment]::SetEnvironmentVariable($Name, [Runtime.InteropServices.Marshal]::PtrToStringBSTR($pointer), "Process") }
  finally { [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($pointer) }
}
Set-SecretEnvironmentVariable "SOMCHAI_SIGNING_STORE_PASSWORD" "Keystore password"
Set-SecretEnvironmentVariable "SOMCHAI_SIGNING_KEY_PASSWORD" "Key password"
~~~

Do not save this helper in a tracked script; paste it into the current terminal session only.

## 3. Check versionCode before building

The current checked-in configuration is applicationId **com.somchai.ai**, versionCode **10**, versionName **1.9.0**. Compare it with the installed app first:

~~~bash
adb shell dumpsys package com.somchai.ai
~~~

The release versionCode must be strictly greater than the installed app's versionCode. If it is not, increment only version metadata in app/build.gradle.kts; do not change applicationId or signing config. Record the old/new values in the test log.

## 4. Build the owner-signed release APK

From repository root:

~~~bash
./gradlew :app:assembleRelease
~~~

Expected output: app/build/outputs/apk/release/app-release.apk

Do not use the debug APK for updating production: debug has the .debug applicationId suffix and a different signing identity.

## 5. Verify package, version and signing certificate BEFORE installing

With Android SDK Build Tools installed:

~~~bash
apkanalyzer manifest application-id app/build/outputs/apk/release/app-release.apk
apkanalyzer manifest version-code app/build/outputs/apk/release/app-release.apk
apksigner verify --verbose --print-certs app/build/outputs/apk/release/app-release.apk
~~~

Required:
- Application ID output is exactly com.somchai.ai.
- Version code is strictly greater than the installed version code.
- SHA-256 certificate digest exactly matches the digest from the currently installed app.

To extract the installed APK without uninstalling:

~~~bash
adb shell pm path com.somchai.ai
adb pull /data/app/<returned-package-path>/base.apk installed-before-update.apk
apksigner verify --print-certs installed-before-update.apk
~~~

Compare the SHA-256 certificate digest printed for installed-before-update.apk with the new release APK. If they differ, STOP. Do not uninstall, clear app data, or attempt to bypass Android's signature check.

## 6. Install as an in-place update — preserve app data

Only after all checks above match:

~~~bash
adb install -r app/build/outputs/apk/release/app-release.apk
~~~

The -r option requests replacement while retaining app data. Do not run adb uninstall, pm clear, factory reset, or any data-clearing command. If installation reports INSTALL_FAILED_UPDATE_INCOMPATIBLE, stop: the signing certificate does not match. Do not remove the installed app to force installation.

After installation, confirm package/version and open the app. Verify old chats/memory and other existing app data remain present before running the Phase 1 device checklist.

## Safety stop conditions

- Keystore unavailable, password/alias uncertain, or certificate mismatch: stop and locate the original signing material locally.
- Never generate a new keystore as a workaround.
- Never upload the keystore or passwords to GitHub, chat, issue comments, or build artifacts.
- Never uninstall the existing app or clear its data to make an update succeed.
