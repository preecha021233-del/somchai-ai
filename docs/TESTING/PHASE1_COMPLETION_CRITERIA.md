# เกณฑ์การจบ Phase 1 — SOMCHAI AI

เอกสารนี้รวบรวมเกณฑ์ตัดสินการจบ Phase 1 โดยยึดแผนและข้อกำหนดที่มีอยู่ในโครงการ ไม่ลดเกณฑ์เพื่อให้ผ่าน และไม่ถือว่าการ Build หรือ CI ผ่านเท่ากับผ่านการทดสอบบนโทรศัพท์จริง

## 1. ต้องผ่านอะไรจึงจะจบ Phase 1

ต้องผ่านครบทุกส่วนต่อไปนี้

1. **สมองภายในและความเข้าใจภาษาไทย** — ทำงานพื้นฐาน/คำสั่ง/คำนวณได้ถูกต้อง และเมื่อมีโมเดลภายในพร้อมใช้งาน ต้องผ่านเกณฑ์คุณภาพคำตอบภาษาไทย
2. **การคิดวิเคราะห์และตรวจสอบคำตอบ** — คำนวณหลายขั้นได้ ตรวจพบข้อมูลขัดแย้ง ยอมรับเมื่อข้อมูลไม่พอ และไม่สร้างแหล่งอ้างอิงปลอม
3. **การวางแผนและจัดการงาน** — สร้างแผนถูกประเภท บันทึกงาน/สถานะได้จริง คงอยู่หลังเปิดแอปใหม่ และไม่กล่าวอ้างว่าทำงานภายนอกแล้วทั้งที่ยังไม่ได้ทำ
4. **ความจำในเครื่อง** — เพิ่ม ค้น เรียก ลบ สำรอง และกู้คืนข้อมูลได้ โดยรักษา ID และเนื้อหาให้ตรงกัน
5. **การค้นคว้าและปลั๊กอิน** — สิทธิ์ต้องได้รับอนุมัติก่อนใช้งาน การค้นจริงต้องเปิดอ่านอย่างน้อย 2 แหล่ง และอ้างอิงเฉพาะหน้าที่อ่านจริง
6. **ความปลอดภัยและการกู้คืน** — ปฏิเสธสิทธิ์/ปลั๊กอินที่ไม่ได้รับอนุญาต ป้องกัน prompt injection สำรองข้อมูลแบบเข้ารหัส กู้คืนได้ตรง และปฏิเสธไฟล์/URL ที่ไม่ปลอดภัย
7. **ขอบเขตสมองและการไม่พึ่ง AI ภายนอกโดยปริยาย** — แชตทั่วไปต้องผ่าน Local-first Brain; เมื่อโมเดลใช้ไม่ได้ต้อง fallback อย่างชัดเจน; ห้ามเรียก AI ภายนอกเองโดยไม่มีคำสั่ง `/ai` ที่เจ้าของเลือกใช้
8. **โมเดลภายในบน Android จริง** — ดาวน์โหลดโมเดลที่กำหนด ตรวจ SHA-256/GGUF โหลดด้วย llama.cpp บนอุปกรณ์ ARM64 และสร้างคำตอบไทยได้อย่างเสถียร พร้อมวัดเวลา หน่วยความจำ อุณหภูมิ และแบตเตอรี่
9. **Learned Skills** — เรียนรู้เป็นร่างเข้ารหัส ต้องมีชุดทดสอบ 2–10 กรณี ผ่านทุกกรณีก่อนเจ้าของอนุมัติ และเรียกใช้เฉพาะ Skill ที่อนุมัติแล้ว; Skill ต้องไม่รันโค้ดหรือเพิ่มสิทธิ์เอง
10. **ติดตั้งอัปเดตโดยรักษาข้อมูลเดิม** — ใช้แอปที่ลงนามด้วย certificate เดิม อัปเดตทับแอปเดิมได้ และข้อมูลเดิมยังอยู่
11. **รายงานปิด Phase 1** — สรุปผลทุกข้อพร้อมหลักฐาน ข้อบกพร่องที่เหลือ และคำตัดสิน ACCEPT เท่านั้นเมื่อผ่านครบ

เกณฑ์ย่อยสำคัญ:
- P01–P08: คำสั่ง/คณิตศาสตร์แบบกำหนดผลแน่นอนต้องผ่านทั้งหมด และเมื่อโมเดลติดตั้งพร้อม ต้องได้อย่างน้อย 18/20 ตาม rubric คุณภาพคำตอบ หากยังไม่มีโมเดล ให้เป็น BLOCKED ไม่ใช่ PASS
- P09–P12: ผ่าน 4/4
- P13–P16: ประเภทงานถูกต้อง บันทึกสถานะคงอยู่หลัง restart และมี audit event ตามที่กำหนด
- P17–P21: ผ่าน 5/5 และ backup/export-import ต้องรักษา ID กับเนื้อหา
- P22–P25: ก่อนอนุมัติต้องไม่มี network request; หลังอนุมัติต้องอ่านหน้าเว็บจริงอย่างน้อย 2 หน้าและอ้างอิงตรวจย้อนกลับได้
- P26–P32: กรณีปฏิเสธต้องถูกปฏิเสธทั้งหมด; การกู้คืนต้องตรง; ไฟล์/ปลายทางอันตรายต้องถูกปฏิเสธ
- P33–P35: ผ่าน 3/3; ต้องมีหลักฐานยืนยันเส้นทางเครือข่ายจริง ไม่ใช่อาศัยข้อความตอบของแอปอย่างเดียว
- P36–P39: ตรวจไฟล์/แฮช โหลดโมเดล และ inference บนโทรศัพท์จริงได้อย่างเสถียร; Build native ผ่านอย่างเดียวไม่พอ
- P40–P43: ผ่าน 4/4 บนอุปกรณ์จริง โดยโมเดลพร้อมใช้งานและมี audit trail

### รายการตรวจบนอุปกรณ์จริง: 48 จุด

เอกสาร `PHASE1_DEVICE_FINAL_CHECKLIST.md` แตกการตรวจบนมือถือเป็น 6 ชุด รวม 48 จุด:
- A01–A12: 12 จุด — core functions และการอัปเดตทับแอปเดิม
- B01–B07: 7 จุด — research และ permissions
- C01–C12: 12 จุด — network security / DNS rebinding
- D01–D06: 6 จุด — local model และคุณภาพภาษาไทย
- E01–E05: 5 จุด — Learned Skills
- F01–F06: 6 จุด — security acceptance สำหรับ P26B–P32B

**หมายเหตุเรื่องการนับ:** 48 จุดนี้เป็นรายการตรวจเชิงลึกบนอุปกรณ์จริง ซึ่งหลายจุดตรวจซ้ำ/ให้หลักฐานเพิ่มเติมแก่ P01–P43 ไม่ใช่ข้อทดสอบใหม่ที่นำไปบวกกับ 43 เป็น 91 ข้อ ดังนั้นจำนวนข้อ Acceptance หลักที่ใช้ตัดสินคือ **43 ข้อ** และต้องผ่าน device checklist ที่เกี่ยวข้องครบด้วย

## 3. หลักฐานที่ต้องเก็บทุกการทดสอบ

ทุกข้อบันทึก:
- รหัสและเวอร์ชันชุดทดสอบ
- Prompt/คำสั่งที่ใช้จริง และพฤติกรรมที่คาดหวัง
- ผลลัพธ์จริงแบบตรงตามที่แอปแสดง
- สถานะ PASS / FAIL / BLOCKED และเหตุผล
- app version/versionCode, commit SHA
- รุ่นโทรศัพท์, Android version, ABI
- ชื่อโมเดล, hash และ quantization (ถ้าใช้)
- วิธีทดสอบ (unit / CI / manual device), วันเวลา และลิงก์หลักฐาน

ห้ามทำเครื่องหมาย PASS จากการมีโค้ดหรือ unit test เพียงอย่างเดียว หากเกณฑ์ระบุให้ทดสอบบนโทรศัพท์จริง ต้องมีหลักฐานจากโทรศัพท์จริง

## 4. กติกาการตัดสิน

- **PASS:** ทำได้ตรงเกณฑ์และมีหลักฐานตรวจสอบได้
- **FAIL:** ทดสอบแล้วไม่ตรงเกณฑ์
- **BLOCKED:** ยังทดสอบไม่ได้เพราะขาดเงื่อนไข/เครื่องมือ/โมเดล/สิทธิ์ หรือหลักฐานไม่พอ ห้ามนับเป็น PASS
- **ACCEPT:** ทุกข้อบังคับ P01–P43 และ device-level gates ที่เกี่ยวข้องผ่านครบ ไม่มีรายการบังคับค้าง BLOCKED/FAIL
- **INCOMPLETE:** ยังมีข้อบังคับ BLOCKED หรือยังไม่มีหลักฐาน
- **REJECT:** มีข้อบังคับ FAIL ที่ยังไม่ได้แก้และทดสอบซ้ำจนผ่าน

CI ผ่าน, APK Build ผ่าน หรือ native compile ผ่าน เป็นเพียงหลักฐานการพัฒนา ไม่ใช่คำตัดสิน Phase 1

## 5. ความสัมพันธ์กับแผนสร้างโครงการ

แผนดำเนินงานของโครงการที่แบ่งเป็น 53 ระยะ (P01–P53) คือแผนงาน/การส่งมอบ ไม่ใช่จำนวนข้อทดสอบ Acceptance:
- P01–P43 คือชุดความสามารถและเกณฑ์ทดสอบที่ระบุใน Acceptance Suite
- งานแยก A/B และรายการ device checklist เป็นการแบ่งงานและเพิ่มหลักฐานทดสอบ ไม่ได้เพิ่มจำนวน Acceptance ID หลัก
- P52 คือการตรวจอัปเดตแบบ owner-signed โดยรักษาข้อมูลเดิม
- P53 คือการสรุปรายงานผลและคำตัดสินปิด Phase 1

การทำงานครบตามรายการพัฒนา 53 ระยะไม่ได้แปลว่าผ่าน Phase 1 โดยอัตโนมัติ ต้องตัดสินจากผลทดสอบและหลักฐานตามเอกสารนี้
