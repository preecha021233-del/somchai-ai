1. ทำงานบน branch `phase-1/local-brain-runtime` ต่อไป
2. ห้าม Merge หรือปิด PR #14 โดยไม่ได้รับอนุญาต
3. ห้ามถอนการติดตั้งแอป ห้ามล้างข้อมูล และต้องรักษาความสามารถในการอัปเดตทับแอปเดิม
4. ห้ามแก้ปัญหา Native/JNI โดยคาดเดา ต้องตรวจ Crash Log และหลักฐานก่อนสรุปสาเหตุ
5. แยกผลทดสอบ Unit Test, Integration/Regression Test และการทดสอบบนอุปกรณ์จริงออกจากกันอย่างชัดเจน

8. การทดสอบบนมือถือโดยเจ้าของโครงการจะเริ่มเมื่อส่งมอบ APK และได้รับอนุญาตให้เริ่มรอบ 3 เท่านั้น
9. ทุกการแก้ไขต้องมีบันทึกไฟล์ที่เปลี่ยน สาเหตุ ผลทดสอบ และ Commit SHA
10. หากงานใดติด BLOCKED หรือพบสาเหตุใหม่ ให้บันทึกตามจริง ห้ามทำเครื่องหมาย PASS เพื่อให้ทันกำหนด

## 3. Release Gates ก่อนส่ง APK

ต้องตรวจครบทุกข้อที่เกี่ยวข้องก่อนส่ง APK ให้เจ้าของโครงการ:

- [ ] G1: ตรวจสอบและบันทึกสาเหตุ P01/P07/P11/P24 จากหลักฐานจริง หรือระบุ BLOCKED อย่างชัดเจน
- [ ] G2: แก้ Native/JNI ตามสาเหตุที่ยืนยันได้ และ Regression Tests ที่เกี่ยวข้องผ่าน
- [ ] G3: P09–P10 มี Unit Tests ครอบคลุมส่วนลด เงินทอน และงบประมาณ และผ่าน
- [ ] G4: P13–P15 มี Unit Tests ตรวจเนื้อหาตามเกณฑ์ของโจทย์ และผ่าน
- [ ] G5: Task/Memory/Chat Persistence มีผลตรวจแยกประเภท ไม่สรุปเกินหลักฐาน
- [ ] G6: Plugin permission และ Web Search มีหลักฐานการอนุมัติ/ปฏิเสธและการควบคุมเครือข่าย
- [ ] G7: `/ai` จัดการข้อผิดพลาดได้อย่างปลอดภัย
- [ ] G8: APK Build สำเร็จและตรวจเงื่อนไขการอัปเดตทับแอปเดิมโดยไม่ล้างข้อมูล
- [ ] G9: เอกสารผลแก้ไขและผลทดสอบใน GitHub อัปเดต พร้อม Commit SHA

**เงื่อนไขการส่งมอบ:** หาก Gate ที่จำเป็นยังไม่ผ่าน ห้ามระบุว่า APK พร้อมทดสอบรอบ 3 ให้รายงานสถานะ BLOCKED/FAIL และสาเหตุจริงก่อน

## 4. ขอบเขตการทดสอบรอบ 3

1. เมื่อ APK ผ่าน Release Gates แล้ว จึงส่งให้เจ้าของโครงการทดสอบบนอุปกรณ์จริง
2. เริ่มทดสอบตามลำดับ Acceptance Suite P01–P43 โดยไม่ข้ามข้อ
3. ทดสอบข้อที่เคย BLOCKED/FAIL/PARTIAL ซ้ำหลังแก้ไข พร้อมบันทึกหลักฐานใหม่
4. Device Final Checklist A01–F06 ต้องดำเนินการตามรายการและบันทึกผลจริง
5. P25–P43 และรายการ Device Checklist ที่ยังไม่ทดสอบ ต้องไม่ถูกนับเป็น PASS ล่วงหน้า
6. การทดสอบรอบ 3 เป็นการตรวจสอบโดยเจ้าของโครงการบนอุปกรณ์จริง ไม่ถือว่าเสร็จเพียงเพราะการทดสอบภายในผ่าน

## 7. เกณฑ์การรายงานสถานะ

- **NOT STARTED:** ยังไม่ได้เริ่มงาน
- **IN PROGRESS:** กำลังดำเนินงาน มีบันทึกความคืบหน้า
- **PASS:** มีหลักฐานทดสอบตรงตาม expected result
- **FAIL:** ทดสอบแล้วผลไม่ตรงเกณฑ์
- **BLOCKED:** ยังทดสอบ/ดำเนินการต่อไม่ได้ พร้อมระบุสิ่งที่ขาด
- **PARTIAL:** ผ่านเพียงบางส่วนและระบุส่วนที่ยังไม่ผ่าน

ห้ามเปลี่ยนสถานะเป็น PASS จากการอ่านโค้ดหรือ Build อย่างเดียว หากเกณฑ์นั้นต้องการผลบนอุปกรณ์จริง
